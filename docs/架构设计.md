# 多平台视频空闲时间助手 — 架构设计

> 依据：`references/项目可行性分析.md`，以及开发过程中确认的两层架构。
> 状态：插件层与 Hook 层（Windows + Claude Code）均已实现初版。

## 1. 可行性结论

**结论：可行。**

依据（来自可行性分析文档）：

| 技术支柱 | 判断 | 文档依据 |
| --- | --- | --- |
| 标签页打开 / 激活 / 注入脚本 | 可行 | 3.1 |
| 指定标签页播放控制 | 可行 | 3.1 |
| Agent 状态检测 | 可行，需逐 Agent 适配 | 3.2 |
| 前台窗口切换（Windows） | 可行 | 3.3 |
| 有声自动播放 | 受限，需首次用户交互 | 3.4 |
| 账号登录态 | 可行，复用浏览器已有登录态 | 3.5 |

## 2. 两层架构

整个系统只有两层，不设独立的协调器进程：

| 层 | 职责 |
| --- | --- |
| **Hook 层** | 监听各 Agent 的事件；判断当前状态；执行对应代码：打开浏览器、传命令、切换窗口 |
| **浏览器插件层** | 执行浏览器内的一切操作：打开页面、播放 / 暂停、静音、平台适配、配置界面 |

```
┌─────────────────────────────────────────────┐
│ Hook 层（hook/）                             │
│ 事件 → 动作判断 → 执行                        │
│ · 命令行打开扩展命令页                        │
│ · Win32 窗口切换                              │
└───────────────────┬─────────────────────────┘
                    │ chrome.exe "chrome-extension://<ID>/command/command.html?cmd=idle"
┌───────────────────▼─────────────────────────┐
│ 浏览器插件层（extension/）                    │
│ · 读 URL 参数 → 打开页面 / 静音 / 复用标签页   │
│ · content script 暂停与恢复                    │
└─────────────────────────────────────────────┘
```

### 2.1 层间通道

终端用命令行打开扩展页面 URL，命令通过查询串传递：

```
chrome.exe "chrome-extension://<扩展ID>/command/command.html?cmd=idle"
```

- 扩展页面在自身上下文调用扩展 API，不存在"网页访问扩展"的权限问题。
- 【已实测】命令行可以打开 `chrome-extension://` 页面，扩展读到设置并打开目标网站。
- 【未验证】Chrome 已在运行时，这条命令是转交给现有实例还是启动新实例。当前实现假设复用现有窗口。

被否决的方案：`externally_connectable`（需要网页承载，无法承载浏览器控制）、本地 HTTP/WebSocket（需常驻进程）、Native Messaging（需注册表 + 宿主程序，方向相反）。

### 2.2 状态判断

状态判断在 Hook 层，不设中间进程。统一抽象为两个动作：

| 动作 | 含义 | 行为 |
| --- | --- | --- |
| `running` | Agent 正在执行，用户空闲 | 打开或聚焦视频浏览器 |
| `attention` | 需要确认/输入，或任务结束 | 最小化浏览器，回到终端 |

各 Agent 的事件名不同，映射关系写在各自的配置里（当前只有 Claude Code，见 `hook/README.md`）。

## 4. 插件功能

| 功能 | 实现 |
| --- | --- |
| 默认打开平台 | 设置页下拉选择，命令触发时打开 |
| 回到上次页面 | 只记录一个全局 `lastVideoUrl`，打开前用 `fetch` 探测状态码，非 2xx 回退默认页面 |
| 首次启动静音 | 每个浏览器会话只在第一次触发时应用静音设置 |
| 切换到后台自动暂停 | 标签页切走 / 窗口失焦 / 不暂停 |
| 自定义 URL | 任意 http(s) 网址，添加时申请该域名权限 |

界面明暗主题跟随系统设置。

【未验证】`fetch` 探测对 B 站失效视频的识别能力；若 B 站返回 200 的提示页则识别不出来，若 `HEAD` 被拒则每次都回退。

## 5. Hook 功能

Hook 层按「Agent 映射 → 动作编排 → 平台调用」分成三层，新增 Agent 或换平台都只动其中一层。详见 `hook/README.md`。

| 功能 | 实现 |
| --- | --- |
| 动作判断 | `hook/agents/<agent>.json` 提供事件名 → 动作映射，`hook.ps1` 查表 |
| 跳转 | 打开命令页；窗口句柄靠"5 秒内 Chrome 成为前台"捕获 |
| 召回 | 最小化浏览器窗口，激活之前记录的终端窗口 |
| 开关 | `/slacking`（status / pause / resume / on / off），`disable-model-invocation` |

跨 Agent 的统一抽象已经实现：事件名差异被隔离在 `agents/*.json`，动作逻辑与平台调用不随 Agent 变化。跨平台的统一抽象尚未实现，见下方待办。

## 6. MVP 范围

按可行性分析文档第七节：Windows + Chrome/Edge，先支持 Claude Code 与 B 站。暂不实现自动推荐、跨平台统一账号、自动登录、视频内容分析、自动刷量。

## 7. 已知问题与待办

| 项目 | 状态 |
| --- | --- |
| `fetch` 探测回退 | 效果存疑，待决定保留、删除或换 `webNavigation` 状态码 |
| 跨平台 | Hook 层目前仅 Windows（PowerShell + Win32）；Linux 需 xdotool/wmctrl，且 Wayland 无通用方案 |
| PowerShell 版本差异 | 已避开 `[datetime]::UnixEpoch`、`-AsHashtable`、`??`/`?:` 等高版本写法；根本方案是用 C++ / Rust 编译原生可执行文件（TODO，未开始） |
| 扩展 ID 绑定路径 | ID 由扩展目录路径推导，路径或系统变化会导致 ID 改变，需在 manifest 加 `key` 固定 |
| 统一抽象 | 计划把动作逻辑抽到与 Agent、操作系统无关的一层，各 Agent 只提供事件名映射 |
| Codex 适配 | 未开始 |
| 窗口句柄捕获 | 依赖时序，被其他窗口打断时记不到，召回时只切终端不最小化浏览器 |

## 8. 风险与应对

| 风险 | 应对 |
| --- | --- |
| Agent 事件不统一 | 各 Agent 独立映射 |
| 自动播放被拦截 | 首次由用户启动播放 |
| 视频网站页面更新 | 平台适配器独立维护 |
| 窗口频繁抢焦点 | 暂停开关、已在小状态时跳过 |
| 登录态失效 | 提示重新登录，不保存密码 |
| Hook 异常或 Agent 退出 | Hook 内部全部 try/catch，失败静默退出，不影响 Agent |
